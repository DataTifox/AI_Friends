# 连续性与主动跟进优化

本次实现位于 `D:\02 File\WorkSpace\AI_friends`，沿用 Python + PySide6 + SQLite。`docs/需求概设.md` 保留原 V0.1 范围，本文件记录后续增量设计及验收。

## 数据与时间

`data/companion.db` 保留原有 `conversations`、`messages`、`memories`，新增：

| 表 | 用途 |
| --- | --- |
| `summaries` | 对话摘要，包含所属会话、起止消息 ID、内容和生成时间 |
| `followups` | 话题、购买或学习类型、来源消息、可跟进时间、状态、上次提问时间和消息 ID |
| `companion_preferences` | 持久化全局主动关心开关 |

首次升级旧数据库前自动创建 `companion.pre-continuity.db`。原消息不自动删除，API Key 仍只保存在 `.env`。

数据库时间沿用 UTC；消息显示、摘要日期划分、静默时段、按天导出使用北京时间（UTC+8）。

## 查询与上下文

- 历史使用 `(conversation_id, id)` 索引和 `LIMIT`，启动只读最近一页，按 ID 向前分页。
- 消息区向上滚到顶部或点击“加载更早记录”读取下一页，保留浏览位置。
- 模型每次只读取最近 12 条消息、最多 5 条记忆、最近 3 份摘要。总上下文默认限制 16,000 字符，过长消息只截断请求内容，数据库保存原文。
- 当前摘要选择是按新旧顺序，不是按主题搜索；不会把全部历史重新发送给模型。
- 摘要与跟进查询有独立索引；日期导出使用时间索引和流式逐行输出。

## 阶段摘要

一次成功聊天后，最多处理一批旧消息。保留最近 12 条原文，旧消息累积 24 条或属于前一天时，调用模型生成最多 800 字的摘要。通过 `end_message_id` 记录进度，下次从尚未汇总的部分继续。只在成功保存摘要后推进进度；不汇总孤立在批次尾部的用户消息。

摘要模型请求失败不影响已经保存的 AI 回复；下一次成功聊天可重试。网络请求和摘要均在后台线程运行，摘要产生时本轮发送按钮会继续禁用，避免同时写入多轮请求。

长历史首次升级可能需要多轮聊天才处理完积压。当前方案没有把阶段摘要自动转成长期事实：长期记忆仍按明确的偏好、学习、计划、姓名规则提取，避免把摘要推测变成事实。

## 跟进规则

`config/companion.json` 顶部的 `_comments` 为每个字段提供中文说明，不参与策略计算。JSON 本身不支持 `//`、`#` 注释，所以说明保存为独立的标准 JSON 字段；原来不带 `_comments` 的配置仍可加载。手工修改配置文件需要重启，界面保存则立即生效。上下文限制按字符而非 token 计数。

“交互设置”页已经支持全部 13 个策略字段。12 个数值输入框配有整数校验、单位提示和字段说明；主动关心下拉框提供“开启/关闭”，显示文件策略与聊天偏好共同决定的实际状态。聊天里关闭后，进入设置页可看到关闭，界面保存开启可以同时更新文件与数据库偏好。当前沿用 Designer 原有控件名，包括 `contestMaxCharsEdit`、`followupDedlayDaysEdit` 和 `followExpiryDaysEdit` 的拼写。

`app/companion_settings_controller.py` 绑定控件，`CompanionPolicy.validate()` 提供共享校验，`storage/companion_policy_repository.py` 通过临时文件替换保存配置并保留 `_comments`。保存后更新对话、摘要、主动跟进三个模块的运行策略；模型请求期间禁用保存和恢复按钮。

“恢复默认”只把表单填为默认值，不提前写文件或改变运行策略；“保存配置”才提交。保存成功后无需重启；新的等待天数仅作用于以后创建的事项，已有事项的到期时间和冷却记录保留。交互设置页内有独立反馈文本，错误也会在此页提示。

明确的第一人称陈述可创建事项，例如“我今天买了一支笛子”“我准备学习吉他”。购买和学习分开处理；假设、举例、朋友经历不创建事项。提取是有限规则，不保证覆盖所有中文说法。

默认行为：

- 3 天后可以跟进，不是到点强制提醒。
- 前台对话页空闲 120 秒、输入框为空且没有请求时才触发，每 30 秒检查一次。
- 全局最多每 24 小时主动问一次，同一话题间隔至少 7 天。
- 北京时间 22:00–09:00 静默，来源超过 30 天的事项不再提起。
- 用户提及该话题的新进展后，延后跟进；直接回答上一次主动问题也会延后。
- 明确拒绝后停止该话题；全局关闭状态、提问和冷却均持久化。
- 生成失败不消耗提问次数；自动检查失败后至少等待一小时再尝试。
- 程序退出后不检查事项，不推送系统通知。

“关闭主动关心”关闭全部自动跟进，“开启主动关心”重新启用全局功能。“别再问笛子了”停止笛子事项，当前没有单项恢复界面。修改 `config/companion.json` 的 `followups_enabled` 也可关闭本功能；配置文件关闭时优先于聊天中的开启指令。

## 验收

1. 在项目根目录运行 `python main.py`，确认配置仍能回填、原会话仍在。旧库应出现升级前备份文件。
2. 查看消息后的北京时间戳。历史超过 50 条时，滚到顶部或点击按钮，检查更早消息能加载且没有重复。
3. 正常发送消息，确认等待模型时仍能移动窗口、输入文字、切换页面，重复发送不会产生第二次请求。
4. 连续聊天积累旧记录后，检查 `summaries` 中新增摘要及起止消息 ID；原始记录仍保留。生成会使用额外一次 API 调用。
5. 发送“我今天买了一支笛子。”，检查 `followups` 中保存购买类型及来源。到期后，在非静默时段保持前台对话页空闲，观察主动提问。
6. 重启确认不会马上重复提问；发送“别再问笛子了”后，确认该事项状态变为 `dismissed`。
7. 运行 `python tools/export_messages.py 2026-10-12`，检查 JSONL 按北京时间日期筛选。导出已有文件需显式添加 `--overwrite`。
8. 在“交互设置”页修改消息数和静默时间，点击保存，检查文件保留中文说明、运行策略立即更新，重启后仍回填修改值。
9. 点击“恢复默认”，确认表单变为默认值但文件尚未改变；保存后才应用默认值。
10. 清空必填数字或输入超出范围的时间，保存应提示具体字段错误且保留之前的文件。聊天中关闭主动关心后，检查下拉框同步关闭；在界面选择开启并保存后恢复启用。

不想等待三天时，用离线回归测试模拟时间推进和重启；测试不修改真实数据库，不使用真实 API Key：

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
python -m unittest discover -s tests -v
```

测试覆盖旧库备份与保留数据、5,000 条消息的索引分页、摘要区间与失败重试、日期边界、上下文限额、跟进冷却/拒绝/静默、后台窗口响应，以及 UI 空闲和输入状态约束。
